- **句柄机制**（关键）：算法吃富对象（`Candidate`/`ExplorationSample`/`KnowledgeBase`/`Evaluation`），无法过 JSON。`HandleStore` 分配不透明句柄 `h_<hex>`，LLM 只能引用上游**真实产出**，无法构造内部对象绕过校验——与 M1 `historical_ref` 同理。`_require_handle` 只认 `h_` 前缀，保留句柄（`client:explorer`）不可经此路径取出。
- **四类调度护栏 + 封存泄漏**：`unknown_tool` / `forbidden_argument` / `missing_argument`·`unexpected_argument` / `bad_handle` / `sealed_leak` / `tool_raised`。`FORBIDDEN_TOOL_ARGUMENTS` 14 个（`grade`/`p_value`/`conclusion`/`causal`…）。
- **AST 边界自检**（`self_check`，非文本匹配）：`NOT_PROVIDED_BY_P18`（11 名）+ `FORBIDDEN_ACCESS_NAMES`（8 名）。**要点**：必须从「被访问名」里剔除**本地绑定名**（参数名/赋值名），否则 `ledger = BudgetLedger()` 这类局部变量会撞 M1 账本入口名造成假阳性。

**踩坑与修复（4 处，均属既有经验的复用）**：
1. **封存键守卫假阳性**：M8 `ARCHIVE_SEALED_KEYS` 含 `source`/`source_ref`，而 M5 `complexity` 的合法输出键恰是 `source` → 若直接复用 M8 的 `check_no_sealed_leak` 会误杀。解法：M10 自建校准守卫 `LEAK_GUARD_EXEMPT_KEYS={"source","source_ref"}`，`M10_SEALED_KEYS = ARCHIVE_SEALED_KEYS − 豁免`。**再次印证「宁窄勿宽」**。
2. **两种知识对象不可混用**：M8 `KnowledgeVersion`（证据等级）≠ M5 `KnowledgeBase`（新颖度）。`m05.novelty` 要后者，误传前者被**类型守卫**拦下（`rejected`/`bad_handle`，而非 `failed`）——这是更好的行为。
3. `fit_relation` 需同时接受 `Candidate` 与 `Ast` 句柄（预拟合链用 Ast）；`gain_against` 需 `_as_fit_result()` 拆 `RelationFit.candidate`。
4. **变异测试还原的假警报**：`diff /tmp/toolbox_orig.py` 报全行不同——实为 `/tmp` 备份 LF、工作区 CRLF（`core.autocrlf=true`），**非内容差异**。教训：**行尾不一致时 `diff` 会全行报错，须先用 `read_bytes().count(b"\r\n")` 核实，勿据此判定文件损坏**。
