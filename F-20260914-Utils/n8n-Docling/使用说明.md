# n8n + Docling → DeepSeek → Obsidian

这套流程在 Windows 本机运行：**上传 PDF / DOCX → Docling 提取 → 按要求切分 → DeepSeek 翻译 → 复核 → 添加重点标记 → 写入 OG-blog**。

## 日常使用

1. 双击本文件夹里的 **Start.vbs**。它在后台启动 n8n 和 Docling，就绪后打开上传入口。首次启动或模型加载期间需要稍等。
2. 打开[文档上传入口](http://127.0.0.1:5678/form/og-blog-translate)。
3. 选择一个 PDF 或 DOCX，设置翻译批次长度、PDF 页码范围及术语表，然后提交。
4. 等待完成提示，在 Obsidian 的 **OG-blog** 中打开本次书籍文件夹。**每个正文章节对应一篇笔记，文件名和一级标题都是章节名称。**

管理入口：[n8n](http://127.0.0.1:5678)。工作流名称：**PDF Word → DeepSeek 翻译复核 → OG-blog**。

输出目录：`D:\Obsidian\ob\OG-blog`。

**Stop.vbs** 会停止这套服务；请在文档处理完成后使用。服务随本机运行，不设置开机自启。关闭网页不会停止已提交的任务。

## 上传参数

| 参数 | 用法 |
| --- | --- |
| 文档 | 每次一个 `.pdf` 或 `.docx`。旧版 `.doc` 先用 Word 另存为 `.docx`。 |
| 按正文章节 | 识别章标题，将各小节归入所属章节；不把小节单独保存成笔记。 |
| 每段字符上限 | 默认 6000，可填 1000–16000。只控制同一章内的 API 翻译批次，输出时会合并成完整章节。这是保护代码、公式和图片后的字符数，不是 token 数。 |
| PDF 起止页 | 从 1 开始，按 PDF 文件实际页序计数；结束页留空或填 `0` 表示末页。Word 忽略这两个字段。 |
| 术语表 | 可留空；建议每行 `英文术语 = 中文译名`，翻译与复核共同使用。 |

例如只翻译 PDF 的第 13–18 页：起始页填 `13`，结束页填 `18`。正文页脚印刷页码可能与文件实际页序不同。

表格不会从行中间截断。若单个表格超过上限，流程会提示提高上限或单独处理该表格。

## 输出文件

同一次处理创建独立书籍文件夹，名称包含**原文件名、时间和执行编号**，避免覆盖其他书籍或之前的版本。文件夹中包含：

- `进程管理.md`、`进程调度.md` 等：完整的章节中文笔记，含该章各小节及重点标记。
- `assets/`：正文中实际引用的插图。
- `处理记录.json`：各章对应关系、复核提示和代码格式统计。

**不导入封面、目录、前言、序言、致谢、作者介绍、参考书目或索引，也不额外生成目录笔记、原文笔记、复核全文笔记。** 正文章节内的概述、结论和小节会保留。识别不到可靠章节边界时会报错，需检查提取结果或限定正文页码。

源码恢复分行和缩进，C 使用 `c`，命令行使用 `bash`，汇编使用 `asm`，构建片段使用 `makefile`，日志等使用 `text` 代码块。相邻且属于同一种语言的代码片段会合并。C 格式化检查非空白字符及字符串内容，避免修改代码本身；格式化不会补造 PDF 中已经缺失的代码或修复 OCR 语法错误。

代码、公式和图片标记在翻译阶段受保护。正文重点排版添加粗体和高亮，不改写句子；无效的强调建议会跳过，排版失败时保留复核译文。Windows 文件名中不能使用的斜杠等字符会替换为全角形式，例如 `块 I／O 层.md`。

## DeepSeek 配置

工作流使用 **DeepSeek API** 凭据，类型为 OpenAI 兼容凭据，Base URL 为 `https://api.deepseek.com`。它复用了你在本机填写的 DeepSeek 配置。

工作流的三个 DeepSeek HTTP 节点共用这份凭据。后续更新密钥只需修改该凭据。n8n AI 助手里的 `AI Assistant model` 是另一份配置，不参与文档翻译。

在 **配置与检查** 节点中可以修改：

| 配置 | 当前值 |
| --- | --- |
| `apiBase` | `https://api.deepseek.com` |
| `translationModel` | `deepseek-flash` |
| `reviewModel` | `deepseek-flash` |
| `styleModel` | `deepseek-flash` |
| `outputDir` | `D:/Obsidian/ob/OG-blog` |
| `doclingUrl` | `http://127.0.0.1:5001` |

更换接口时，同时修改凭据中的 Base URL 和上述 `apiBase`，并选择该接口支持的模型。若目标接口不支持 DeepSeek 的 `thinking` 参数，需要从三个请求准备节点中删除该参数。改完保存并 **Publish**，生产上传入口才会使用新版本。

`outputDir` 可以设置为 OG-blog 内的子目录。专用写入节点只允许写入 `D:\Obsidian\ob\OG-blog`，自动创建书籍文件夹，拒绝覆盖已有的不同内容。若确实需要换 Obsidian 库，还需同步修改 `environment.ps1` 的限制和 `nodes/ObsidianChapterWriter.node.js` 中的 `ALLOWED_ROOT`，然后重新启动 n8n。

## 复核与费用

每段通常调用 **3 次 API**：翻译、复核、选择重点；网络失败时最多重试 3 次。费用由 DeepSeek 按实际调用收取。文档文字与术语表会发送给 DeepSeek；Docling 解析在本机进行，提取的图片不会以 Base64 送入这些翻译请求。

==自动复核不能证明或保证 99% 翻译准确率。== 流程会检查输出是否被截断、代码/公式/图片标记是否完整，以及部分数值是否遗漏；这些检查不能发现所有语义错误。扫描件的 OCR、复杂表格、否定条件、专有名词和关键数字仍需对照原文验收。

## 失败时如何处理

- **Could not find execution**：该编号的执行记录不存在或已被清理，不一定表示翻译失败。先到 OG-blog 查看对应书籍文件夹。本工作流保存成功、失败和手动执行记录，按本机设置保留 7 天；修改前已清理的历史详情不能补回。
- **查看 Executions**：打开失败执行，检查红色节点的错误。翻译或复核失败时不会进入文件生成步骤。
- **401 / 403**：检查实际使用的 `DeepSeek API` 凭据及 DeepSeek 账户权限。
- **模型不存在**：在「配置与检查」中填入该账户支持的模型名称。
- **输出被截断**：减小每段字符上限，重新提交。
- **保留标记发生变化**：模型改动了代码、公式或图片占位符，流程会停止，避免导入损坏的译文。
- **复核未提供问题清单**：只要复核译文完整且通过保留标记检查，流程会继续，并在 `处理记录.json` 中标记该章需要人工核对；缺少译文仍会停止。
- **文档提取失败**：先尝试较小的 PDF 页码范围；扫描件检查清晰度，密码保护文件先解锁。
- **页面打不开**：运行 `Start.vbs`，等待启动；日志位于本工作区的 `work\n8n-docling\logs`。

全部章节处理成功后才开始写文件；磁盘写入不是事务，若此阶段失败，可能留下部分文件。同一次执行续跑时，写入节点会跳过内容完全相同的文件；遇到不同内容会停止，避免覆盖用户修改。

已经完成部分分段的执行失败后，优先在该执行的菜单中选择 **Retry with currently saved workflow**，从失败节点使用修复后的工作流续跑。不要直接重新上传整本文档，否则会从头解析与翻译。只有执行记录仍保留、节点名称及结构兼容时，才能恢复原先的中间结果。

安装目录与数据库位于本工作区的 `work\n8n-docling`，启动文件依赖它，**不要只移动 outputs 文件夹或删除 work 目录**。备份 n8n 时请同时备份其数据库与加密配置；仅复制工作流 JSON 不包含密钥。
