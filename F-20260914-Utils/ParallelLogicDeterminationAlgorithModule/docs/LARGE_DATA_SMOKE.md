# 大数据 smoke：2048×2048 矩阵

执行日期：2026-09-14。测试脚本：[large_data_smoke.py](../tests/large_data_smoke.py)。原始报告：[large-data-validation.json](large-data-validation.json)。

**结果：CPU、RTX 5060 Laptop GPU、Intel 核显、Intel AI Boost NPU 的矩阵乘法和逐元素加法全部通过。** 当前 PLDA 路径与另行测量的上下文复用路径都验证了结果。

## 规模与验收口径

- 输入：两个 `2048×2048` float32 矩阵，共 **32 MiB**；每个输出 **16 MiB**。
- 矩阵乘法约 **17.18 GFLOP**（约 172 亿次浮点运算，按 `2N³` 计）；是原 64×64 测试计算量的 32768 倍。
- 数据：固定种子 `20260914`，非恒定随机正负二进制分数 `±1/32`。这类输入可以在较低精度下精确表示，适合验证数据搬运、shape、算子和结果完整性；不代表任意浮点数据的精度表现。
- 参考：NumPy float64 矩阵乘法/加法。每个输出比较全部 **4,194,304** 个元素，并检查形状和有限性。
- 预设容差：`abs(error) <= 1e-5 + 1e-4 * abs(reference)`；实测这组输入上最大绝对误差均为 **0**。
- 每种设备均单独作为模块的唯一候选，任务禁止重试，不存在 CPU 回退通过加速器测试的情况。
- 各设备统一一个任务槽位；CPU 原生库线程数限制为 1。每个任务显式预留 64 MiB workspace，单次尝试期限为 180 秒。

## 当前 PLDA 路径：包含两个任务的完整作业

使用现有 `PLDAModule` 执行矩阵乘法和加法，保留逐任务进程启动、传输、结果验证与提交、进程退出以及 OpenVINO 编译调用。

| 设备 | 完整作业耗时 | 数值检查 |
| --- | ---: | --- |
| CPU / NumPy，单线程 | 0.667 s | 2/2 通过 |
| RTX 5060 / CuPy CUDA | 1.468 s | 2/2 通过 |
| Intel Graphics / OpenVINO GPU.0 | 13.782 s | 2/2 通过 |
| Intel AI Boost / OpenVINO NPU | 6.388 s | 2/2 通过 |

以上为单次 smoke 的端到端时间，不是稳态吞吐，也没有把启动、退出和编译误记成纯内核计算。

## 独立实验：复用上下文/模型后的调用耗时

此实验位于测试脚本中，**没有把常驻进程或缓存优化集成进 PLDA**。每个设备在一个实验进程内复用上下文，每个 OpenVINO 算子只创建一个编译模型和 infer request。先执行首次调用，再预热 2 次，正式采样 7 次，取中位数。

计时包含从主机输入到主机可读输出的调用过程。CUDA 每次仍执行 H2D 和 D2H；OpenVINO 每次提交主机输入并复制返回结果；CPU 使用 NumPy 返回主机数组。初始化、编译、校验参考值和实验进程退出不在稳态调用计时内。首次调用可能命中先前测试的驱动/磁盘缓存，因此不称作完全冷启动。

| 设备 | 首次矩阵乘法 | 复用矩阵乘法中位数 | 首次加法 | 复用加法中位数 |
| --- | ---: | ---: | ---: | ---: |
| CPU / NumPy，单线程 | 123.948 ms | **125.111 ms** | 5.771 ms | **5.411 ms** |
| RTX 5060 / CuPy CUDA | 84.500 ms | **11.202 ms** | 44.416 ms | **9.126 ms** |
| Intel Graphics / OpenVINO GPU.0 | 26.693 ms | **28.440 ms** | 17.846 ms | **17.791 ms** |
| Intel AI Boost / OpenVINO NPU | 48.712 ms | **29.870 ms** | 23.471 ms | **18.474 ms** |

此测试中，复用路径的 RTX 矩阵乘法约为单线程 CPU 的 **11.2 倍**，Intel 核显约 **4.4 倍**，NPU 约 **4.2 倍**。加法仍是 CPU 最快。这里的比较限定了输入规模、线程配置、数值模式和计时边界，不是所有算法或完整应用的加速承诺。

原始 JSON 还包含 CUDA 数据驻留时的 event 计时；它不包含主机往返，不能与表中的完整调用时间混用。

## 复现

在模块目录执行：

```powershell
.\.venv\Scripts\python.exe -m tests.large_data_smoke --size 2048 --repeats 7 --output docs/large-data-validation.json
```

测试中间的大数组文件位于专用临时目录，结束后清理。输出报告保存元数据、误差统计与事件，不保存几十 MiB 的完整矩阵。

本次结果表明：较大的矩阵乘法已能显示加速器在复用路径中的收益，而 PLDA 当前的逐任务初始化开销仍明显。数据大小之外，算子的计算密度、内存访问及上下文复用情况也必须纳入调度成本模型。
