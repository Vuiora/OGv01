# Linux 2.6 时代的调度策略与 CFS

本文以《Linux 内核开发》第三版所处的 Linux 2.6 时代为背景。
SCHED_NORMAL 是普通任务的调度策略，CFS 是普通任务公平调度的实现算法。
SCHED_NORMAL 与 CFS 不是同一层次的概念：前者规定策略，后者实现普通任务的调度。
普通任务由 fair_sched_class 处理；这一时期该调度类的核心算法是 CFS。

Linux 提供 SCHED_FIFO 和 SCHED_RR 两种实时调度策略，由 rt_sched_class 处理。
实时调度类优先于普通公平调度类，但还需要考虑实时带宽限制等条件。
CFS 不负责调度 SCHED_FIFO 和 SCHED_RR 实时任务。

SCHED_FIFO 没有时间片轮转，同优先级任务按先后次序运行。
任务可以因阻塞、退出、主动让出 CPU 或被更高优先级实时任务抢占而停止运行。
SCHED_RR 在相同实时优先级的任务之间按时间片轮转。
较低优先级的实时任务不会仅因为较高优先级任务的时间片耗尽而获得运行机会。

经典 CFS 通过 vruntime 表示任务的虚拟运行时间，倾向于选择 vruntime 较小的可运行任务。
nice 值通过权重影响 vruntime 增长速度，从而影响普通任务之间的 CPU 时间分配。
以上表述只用于解释该历史背景中的概念关系，不应直接当作所有现代内核版本的完整调度说明。
